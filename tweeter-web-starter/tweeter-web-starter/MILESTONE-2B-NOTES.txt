2b passoff notes
 
Template Method
- PagedPresenter.loadMoreItems()
- Shared paging steps; subclasses override getMoreItems() and
  getItemDescription() for feed/story/followers/followees.
- Why: write the loading algorithm once, keep feature differences separate.

Generics
- PagedPresenter<T, U>: T = User or Status, U = the service type.
- ItemScroller<T> uses the same type for items and rendering.
- Why: reuse the code while keeping types consistent.

Functions as parameters
- Presenter.doFailureReportingOperation() takes the work as a callback.
- AuthenticationPresenter.authenticate() takes a login/register callback.
- Why: the operation changes, but error handling/authentication steps don't.

Inheritance
- Presenter<V> stores the view; BusyPresenter shares loading handling.
- PagedUserItemPresenter / PagedStatusItemPresenter share createService().
- Why: subclasses reuse common state and behavior instead of copying it.

Extract method / parameterization
- credentialsMissing(): common login/register validation.
- UserInfoPresenter.changeFollow(): boolean selects follow or unfollow.
- FollowService.simulateFollowChange(): shared delay and count retrieval.
- Why: same steps belong in one place; parameters cover small differences.

Component reuse / composition
- ItemScroller: shared scrolling; function props supply presenter/rendering.
- UserItemLayout: shared author row; children adds status content.
- LoadingButton, AuthenticationFields: shared UI markup.
- useAuthenticationView: shared login/register state and callbacks.
- Why: reuse view behavior and layout across screens.

Remember
- Template Method = subclass overrides. Function parameters = callbacks.
- finally clears loading/toasts even on failure.
- Small feature-specific overrides are intentional.
